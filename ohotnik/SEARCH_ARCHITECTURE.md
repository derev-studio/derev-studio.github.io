# Охотник за скидками — единая система поиска

Дата архитектуры: 15 ноября 2026 года.

## Цель
Один запрос на русском («отвёртка», «плеер», «хлеб», «рюкзак», «форель»)
показывает карточки **реальных товаров**, а не случайные результаты и не
главные страницы магазинов. Источники товаров добавляются целыми каталогами,
а не отдельными правками под одно слово.

## Источники и текущее состояние
- **Продуктовые магазины**: официальный открытый реестр цен / over.org.il.
  Получаем цены, магазины, город, дату и штрихкод. Этот реестр не обязан
  содержать фотографию или URL покупки.
- **KSP**: есть несколько подтверждённых карточек в `catalog.json`.
  Массовые запросы к API из GitHub Actions возвращали HTTP 403.
  Статус: подключён частично; нельзя выдавать за полный каталог.
- **Ivory, ACE, Home Center, Zap**: предоставлены внешние ссылки;
  полные разрешённые продуктовые фиды пока не подключены.
- **Форель Дана**: небольшой каталог с ценами и изображениями от производителя.
- **PriceDrop**: использовать как пример дизайна и как ссылку для пользователей.
  Правила запрещают автоматическое массовое копирование (scraping).

## Единая модель данных
**Product**:
- `id` — GTIN/EAN для упакованных товаров, иначе нормализованный код производителя
  + конкретная модификация.
- `title_ru`, `title_he`, `brand`, `category`, `model`, `unit`.
- `image_url`, `image_origin`, `image_verified_for_gtin`.
  Если фото приблизительное, показывать «Иллюстрация»; нельзя подменять товар.
- `offers[]` — по одному предложению каждого конкретного продавца/филиала:
  `store_id`, `chain_name`, `branch`, `price_ils`, `price_per_unit_ils`,
  `in_stock` (или `unknown`), `checked_at`, `product_url`, `source`.
  **Никогда** не присваивать одному продавцу цену другого.

## Ранжирование поиска
1. Запрос нормализуется (регистр, орфография, русские/ивритские синонимы).
2. Запросу определяется класс: продукты, электроника, бытовые, инструменты,
   товары для животных, другие материальные товары.
3. Поиск ведётся по **всем** подключённым каталогам параллельно, с
   дедупликацией по штрихкоду / бренду и точной модели.
4. Строгая проверка соответствия: «курица» не означает суп или корм;
   «лосось филе» не означает консервы; «FiiO DM15» не означает DM13.
5. Показывать цену, фото, магазин и кнопку «Открыть именно этот товар»
   только когда `product_url` относится к той же модификации товара.
6. Фильтры города, сети, цены, наличия, категории и типа доставки.

## Обновление
- Разрешённые фиды магазинов (CSV, XML, JSON, API и schema.org Product/Offer)
  загружаются отдельно через серверный сборщик.
- Проверки и обновления запускаются планировщиком, с ограничением запросов,
  уважением robots.txt, правил доступа, лицензий изображений.
- Последние корректные данные можно кешировать с датой проверки;
  неудачная загрузка **не** означает, что магазин не продаёт товар.
- GitHub Pages достаточно для интерфейса и заранее собранного
  каталога. Для **живого универсального поиска по всем магазинам**
  понадобится доступный постоянно серверный API либо лицензированный
  агрегатор. Выключенный домашний Mac не должен быть сервером.

## Что уже сделано
- Единое поле поиска и маршрутизация популярных категорий.
- Продуктовые предложения через открытый реестр цен.
- Унифицированные карточки магазинов и товаров, несколько каталогов.
- Запасной поиск на внешних площадках, если данные недоступны.

## Что нельзя называть готовым
- Полный каталог всех товаров всех магазинов.
- Автоматическое получение цен и изображений в KSP, Ivory, ACE и других
  магазинах при недоступном API.
- Универсальный перевод любого редкого русского термина без
  проверенного сервиса перевода.
- Кнопку «Открыть товар в магазине», если известен только адрес его
  главной страницы / страницы поиска.

## Порядок подключения новых источников
1. Получить доступ к разрешённому фиду/партнёрскому API магазина.
2. Создать адаптер `source -> Product/Offer`.
3. Верифицировать цену, фото, продуктовый URL на примерах.
4. Добавить источник в индекс и отслеживать свежесть.
5. Повторить для следующего магазина без переделки пользовательского интерфейса.
